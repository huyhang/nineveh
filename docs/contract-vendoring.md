# Vendoring a client contract

How to consume Nineveh's agent API from a separate repository. A native
reading app follows the same steps with a different file; see
[Vendoring the app contract](#vendoring-the-app-contract).

The short version: copy `docs/librarian-openapi.json` into your client repo,
record which commit it came from, and add one test that tells you when it has
gone stale. No submodule, no build-time network call.

## Why the slice and not the whole document

`docs/openapi.json` describes all 60 operations Nineveh publishes. A librarian
agent calls eight of them. If you vendor the full document, every unrelated
change — a reader endpoint, a metadata filter — shows up as a diff in your
client repo and you have to work out whether it affects you.

`docs/librarian-openapi.json` carries only the `librarian`-tagged operations
and the schemas they reference. It is 1,155 lines instead of 5,511, and it
changes only when the surface you actually call changes. That is the signal
worth reacting to.

Every contract file is regenerated by `python scripts/export-openapi.py` and
verified by `tests/test_contract.py`, which fails if any of them drifts from
the live route table. Each slice is additionally checked for dangling `$ref`s
and security schemes, so it is safe to feed straight to a code generator.

---

## Step 1 — Take a copy

From your client repository, with Nineveh checked out alongside it:

```sh
mkdir -p contracts
cp ../nineveh/docs/librarian-openapi.json contracts/
```

Or pull it from a running instance, which is convenient when Nineveh lives on
the NAS and you are working elsewhere:

```sh
curl -fsS http://nineveh.your-tailnet.ts.net/openapi.json \
  | jq '{openapi, info,
         paths: (.paths | with_entries(select(.key | test("^/api/v1/librarian/"))))}' \
  > contracts/librarian-openapi.json
```

Anchor that pattern. A bare `test("/librarian/")` also matches
`/api/v1/admin/librarian/activity`, which is the operator's endpoint and has no
business in an agent's contract.

Prefer the file copy regardless. The `jq` form drops `components`, so any
schema reference in it will dangle — it is a stopgap, not a substitute.

## Step 2 — Record where it came from

A vendored file with no provenance becomes a mystery within a month. Write a
sibling file next to it:

```sh
cat > contracts/SOURCE <<EOF
source:   nineveh
commit:   $(git -C ../nineveh rev-parse HEAD)
version:  $(jq -r .info.version contracts/librarian-openapi.json)
sha256:   $(shasum -a 256 contracts/librarian-openapi.json | cut -d' ' -f1)
taken:    $(date -u +%Y-%m-%dT%H:%M:%SZ)
EOF
```

**Pin on the `sha256`, not on `version`.** Nineveh's `info.version` tracks the
package and bumps on releases that leave the agent surface untouched. The
hash changes exactly when your eight operations change, which is the question
you want answered.

## Step 3 — Add a drift test

The mirror of Nineveh's own contract test: Nineveh proves its committed
document matches its routes, and you prove your copy matches Nineveh.

```python
# tests/test_contract.py
import json
import os
from pathlib import Path

import httpx
import pytest

VENDORED = Path(__file__).parent.parent / "contracts" / "librarian-openapi.json"
NINEVEH = os.environ.get("NINEVEH_URL", "http://localhost:8080")


def librarian_slice(document: dict) -> dict:
    """The same filter Nineveh applies, so the two are comparable."""
    paths = {
        path: {
            method: operation
            for method, operation in item.items()
            if isinstance(operation, dict)
            and "librarian" in (operation.get("tags") or [])
        }
        for path, item in document["paths"].items()
    }
    return {path: item for path, item in paths.items() if item}


def test_the_vendored_contract_still_matches_nineveh():
    """Skipped when Nineveh is unreachable, so offline work is not blocked."""
    try:
        live = httpx.get(f"{NINEVEH}/openapi.json", timeout=3).json()
    except httpx.HTTPError as unreachable:
        pytest.skip(f"Nineveh not reachable: {unreachable}")
    vendored = json.loads(VENDORED.read_text())
    assert librarian_slice(live) == vendored["paths"], (
        "contracts/librarian-openapi.json is stale — re-copy it from Nineveh"
    )
    carried = vendored.get("components", {}).get("schemas", {})
    published = live.get("components", {}).get("schemas", {})
    assert {name: published.get(name) for name in carried} == carried, (
        "a schema in contracts/librarian-openapi.json is stale — re-copy it"
    )
```

Compare the schemas as well as the paths. A path names its request and
response bodies only by `$ref`; their fields live in `components.schemas`, so
a renamed field changes a schema and leaves every path as it was. The slice
carries exactly the schemas it references, so checking those names covers
everything your client sends or decodes, and a newly referenced schema shows
up as a changed path.

Skipping rather than failing when the server is down matters: you want this
test to run on every local `pytest`, and it is useless if it blocks you on a
train.

## Step 4 — Generate a typed client (optional)

Useful because the thing calling your tools is a small model that will not
notice a malformed response. A type error at build time is much cheaper than
a confused answer at run time.

```sh
uvx openapi-python-client generate --path contracts/librarian-openapi.json
```

Every response references a schema, so the generated client returns typed
objects rather than dictionaries, and the drift test catches a response field
that is renamed or removed. No schema sets `additionalProperties: false`, so a
field Nineveh adds later is ignored rather than rejected. Every operation
requires the `LibrarianToken` bearer scheme; `AuthenticatedClient(base_url=...,
token="nvh_...")` sends it.

Commit the generated package and regenerate whenever step 5 runs. The same
document can also drive your MCP tool definitions — parameter names, types and
bounds are already in it, so the four tool schemas need not be hand-written a
second time and kept in sync by hand.

## Step 5 — The update loop

When Nineveh's agent API changes:

```sh
cd ../nineveh && python scripts/export-openapi.py && cd -
cp ../nineveh/docs/librarian-openapi.json contracts/
# refresh contracts/SOURCE, then:
pytest tests/test_contract.py
git diff contracts/          # review what actually moved
```

The diff is the point. A three-line change to one response is a glance; a new
required field is a real review.

## Vendoring the app contract

`docs/app-openapi.json` is the slice for a native reading app, such as a
macOS or iPadOS client: the 20 operations tagged `authentication`, `opds`,
`pages`, `publications`, `reader` and `series`. That covers the OPDS feeds,
series and publication detail, covers, the page manifest and individual pages,
page-range and full-file downloads, reading progress, and `/api/v1/auth/me`.
Health checks are left out. The unauthenticated `/opds/v2/authentication.json`
already tells an app it has reached an OPDS server, and `/auth/me` tells it
whether the credentials work.

Steps 1–5 apply unchanged with the filename swapped, apart from these:

**The drift test filters by six tags, not one.** Replace `librarian_slice`
with:

```python
APP_TAGS = {"authentication", "opds", "pages", "publications", "reader", "series"}


def app_slice(document: dict) -> dict:
    paths = {
        path: {
            method: operation
            for method, operation in item.items()
            if isinstance(operation, dict)
            and APP_TAGS & set(operation.get("tags") or [])
        }
        for path, item in document["paths"].items()
    }
    return {path: item for path, item in paths.items() if item}
```

**Credentials are a Nineveh user's, over HTTP Basic** — not a librarian token.
An administrator has to grant the account read access to its libraries first.
The slice declares the `HTTPBasic` scheme, so a generator knows the requests
need credentials.

**Generate the Swift client with Apple's `swift-openapi-generator`.** Its build
plugin expects the document inside the target as `openapi.json`, next to an
`openapi-generator-config.yaml` that lists `generate: [types, client]`, so
vendor the file there rather than under `contracts/`. The generator does not
act on security schemes itself; add the `Authorization` header in a
`ClientMiddleware`.

**Responses are typed, apart from the feeds.** The page manifest, progress,
series and publication detail, and `/auth/me` each reference a schema, so the
generated client decodes them and the drift test catches a response field
that is renamed or removed. The OPDS feeds and the authentication document
stay free-form objects under their own media types; decode them with an
OPDS 2.0 model, since they follow a published spec rather than a Nineveh one.
No schema sets `additionalProperties: false`, so a field Nineveh adds later is
ignored by apps already installed instead of failing their decoding. Nineveh's
contract tests keep it that way.

A publication's volume number is `belongsTo.series[].position`, a number, where
OPDS 2.0 puts it. A number nothing can order, such as `12a`, is left out
rather than sent as a string.

**Files arrive as files.** Covers declare `image/webp`, pages declare each
image type the scanner accepts, and full and page-range downloads declare
`application/vnd.comicbook+zip`. The generator hands each body over as an
`HTTPBody` to stream or collect, with its `ETag`. The HEAD operations declare
`ETag` and `Content-Length` and no body, so asking for a download's size costs
no download.

**Decode dates with your own transcoder.** Fields documented as `date-time`
carry Python's `isoformat()` output, such as
`2026-09-16T18:03:45.447849+00:00`, and it leaves the fraction out when it is
zero. The runtime's built-in transcoders use `ISO8601DateFormatter`, which
accepts only one of those forms: `.iso8601` rejects the fraction and
`.iso8601WithFractionalSeconds` requires it. Give the client one that tries
both:

```swift
import Foundation
import OpenAPIRuntime

/// Nineveh sends Python's `isoformat()`: a fractional part only when non-zero.
struct NinevehDateTranscoder: DateTranscoder {
    private let fractional = Date.ISO8601FormatStyle(includingFractionalSeconds: true)
    private let whole = Date.ISO8601FormatStyle()

    func encode(_ date: Date) throws -> String { fractional.format(date) }

    func decode(_ string: String) throws -> Date {
        if let date = try? fractional.parse(string) { return date }
        return try whole.parse(string)
    }
}

let client = Client(
    serverURL: server,
    configuration: Configuration(dateTranscoder: NinevehDateTranscoder()),
    transport: URLSessionTransport(),
    middlewares: [authentication]  // your ClientMiddleware adding Basic credentials
)
```

## Reference: what a librarian client has to get right

**Authentication.** A bearer token issued under **Admin → Librarian**:

```
Authorization: Bearer nvh_...
```

The slice declares it as the `LibrarianToken` security scheme on every
operation, so a generated client knows each request needs it.

The secret is shown once, at creation, and stored only as a hash. There is no
way to recover it — issue a new token instead.

**Capabilities are narrower than read and write.** A token carries some subset
of `catalog:read`, `metadata:read`, `ingest:stage`, `ingest:commit`, and may be
restricted to particular libraries. Calling an endpoint outside its grant
returns `403` with the missing capability named in `detail`.

**Staging and committing are separate.** `POST /api/v1/librarian/ingest`
validates and stages a volume and returns `targetPath` — the exact location it
*would* occupy — without writing to the library. `POST .../{id}/commit` places
it, under a different capability. A client meant to propose from a phone
should hold `ingest:stage` only; `GET /api/v1/librarian/ingest` lists what is
waiting for someone with `ingest:commit` to approve.

**Send `X-Correlation-Id`** on every request in a logical chain. Nineveh groups
the resulting activity rows by it, so a resolve → stage → commit sequence reads
as one entry in the audit feed rather than three unrelated ones.

**Status codes worth handling explicitly:**

| Code | Meaning |
|---|---|
| `403` | The token lacks the capability named in `detail` |
| `404` | Unknown series, library outside the grant, or an expired staged upload |
| `409` | The target filename already exists — placement never overwrites |
| `413` | Body exceeded `NINEVEH_MAX_UPLOAD_BYTES` |
| `422` | Invalid filename, or the archive failed validation |

**Do not trust `confidentMatch` blindly, but do use it.** The resolve response
carries `confidentMatch` and `ambiguous` precisely so the model does not have
to compare raw scores. When `ambiguous` is true, ask rather than guess.

## Gotchas

- **`suggestedFilename` is a proposal, not a rename that already happened.**
  Staging returns both the name you sent and the name that would match the
  series' existing volumes. Pass the one you want back to `commit`.
- **`duplicateOf` is checked against the indexed catalog.** A volume placed
  seconds ago is invisible until the following scan completes.
- **Uploads are `multipart/form-data` with snake_case field names**
  (`series_id`, `filename`, `file`) while responses are camelCase. That is the
  house convention throughout Nineveh, not an inconsistency in this endpoint.
- **The admin token-management endpoints are deliberately absent** from the
  slice. They are the operator's surface, not the agent's; if your client needs
  them it is doing something an agent should not.
